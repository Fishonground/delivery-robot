## Постановка задачи

Доставка заказа клиенту по указанным координатам (упрощение – доступно движение по прямой) при помощи движущегося робота и выдача заказа при условии совпадения места доставки и полученного/ожидаемого пароля (упрощение – клиенту известен правильный пин-код от заказа), возвращение на исходную позицию и завершение работы.

## Известные ограничения и вводные

По условиям организаторов должна использоваться микросервисная архитектура и шина обмена сообщениями для реализации асинхронной работы сервисов.

### Цели и Предположения Безопасности (ЦПБ)
Цели безопасности:
1.	При любых обстоятельствах во время выполнения задания груз не должен быть поврежден или получен не аутентичным лицом
2.	При любых обстоятельствах выполняются только аутентичные управляющие команды оператора наземных управляющих станций
3.	При попытках неавторизованного доступа робот должен вернуться в управляющую станцию
4.	При любых обстоятельствах выполняются только авторизованные задания

Предположения безопасности:
1.	Предполагается отсутсвие физического воздействия на робота
2.	Робот совершает передвижения только по прямой траектории в отсутствии препятствий 
3.  После получения задания робот функционирует автономно (т.е. движется к клиенту, авторизует и выдаёт заказ даже в отсутствие связи с сервером)
4. Сотрудники наземного управляющего центра (fleet) аутентичны 
5. Монитор безопасности и брокер сообщений доверенные модули
6. Сервис для получения заказов безопасен

## Архитектура системы

### Компоненты

- **Client** Абстрактный пользователь, чья задача ввести пин-код. Для этого в рамках реализуемой задачи он пользуется файлом request.rest для редактирования и отправки запросов.
- **Fleet management service (fleet)** Абстрактный сотрудник выдает заказы роботу при помощи файла request.rest, получая на REST интерфейс уведомления о принятии заказа к выполнению и о результате доставки (т.е. в т.ч. и возвращении робота на базу).
- **Communication block (communication)** Разворачивает REST API для приема заказа, передачи его далее по шине, а так же для передачи сообщений подтверждения и результата доставки.
- **HMI (hmi)** Разворачивает REST API для приема заказа и передачи его далее по шине. Поскольку подразумевается автономное функционирование робота, то данный элемент считаем аппаратной составляющей со всеми вытекающими последствиями для безопасности.
- **Positioning (positioning)** Осуществляет функции расчета параметров движения.
- **Sensors (sensors)** Модуль, отвечающий за физическую блокировку и разблокировку грузового отсека (сервоприводы)
- **Motion control (motion)** Осуществляет движение к заданной точке с помощью полученных направления и скорости. С определенной частотой сообщает в центральную систему управления (Central) пройденное расстояние. В результате Central знает о достижении контрольной точки, а Positioning может посчитать новые координаты.
- **Security monitor (monitor)** Обрабатывает все сообщения, проверяет на соответствие имеющихся политик безопасности.
- **Central Control Unit (central)** Принимает сообщения, сохраняет требуемую точку доставки и пин-код, запускает расчет и старт движения движение. При получении сообщения о достижении точки назначения проверяет по координатам соответствие, разрешает считывать пин-код. Проверяет пин-код ограниченное количество раз – при успешном вводе открывает замок, по закрытию замка или при ошибке ввода пин-кода более 3 раз инициализирует движение в управлющую станцию. При достижении пункта назначения инициирует отправку сообщения со статусом заказа через во Fleet.

### Описание Сценариев (последовательности выполнения операций), при которых ЦБ нарушаются

Для определения доверенных компонентов необходимо произвести анализ рисков и сценариев нарушения ЦБ.

Central control Unit — «мозг» системы, и при его компрометации нарушаются цели безопасности (возможность обойти условия).

Целесообразным представляется исключение механизма
навигации из состава Center, поскольку это сильно снижает затраты на проверку.

Поскольку в реальной ситуации выполнение задания будет осуществляться на основе данных от GPS-модуля, Motion (сколько должно быть пройдено по маршруту) и через ИНС (инерциальной системы навигации), то логичным представляется добавление модулей GPS и ИНС, и модуля комплексирования их показаниий.

Таким образом, Positioning производит рассчет движения (скорость и направление),после чего передает их в Motion для осуществления движения и логирования. Также модуль Central сравнивает отклонение от координат задания с реальными координатами робота который, были переданы из модуля комплексирования,в данной системе было реализованно получение не реальных координат а их генерация,так как внедрение системы эмуляции координат является нетривиальной задачей (поэтому предполагается не соответствие координат миссии и модуля комплексирования) 

При таком развитии событий представляется разумным сделать модуль Positioning можно не делать доверенным так как при неправельном подсчете данных для перемещения с помощью модуля комплексирования, можно будет увидеть расхождения реальных координат с заданием. Тогда необходимо сделать доверенными модуль ИНС и комплексированния для того чтобы всегда знать реальные координаты робота

Если будет взломан Motioning или Positioning, злоумышленник сможет не нарушить цель безопасности так как Central всегда будет знать реальные координаты робота и сможет сравнить их с заданием и остановить его выполнение.

Если будет взломан HMI, злоумышленник сможет узнать пин-код что приведет к нарушению ЦБ 1. Поэтому необходимо сделать этот модуль доверенным

Также нарушаются ЦБ 2 и 4, если взломан Communication — поэтому добавим модуль криптографии и сделаем его доверенным он будет выполнять шифрование и подпись данных отправляемых с робота, а также принимать, расшифрововать и проверять подпись принятых сообщений. С помощью этих механизмов можно оставить модуль связи недоверенным, так как данные будут проходить через него в зашифрованном виде и подписанные эл.подписью

Также взлом замков Sensors  позволит злоумышленнику их открыть нарушение ЦБ 1. Таким образом, Sensors следует добавить в доверенные компоненты.

Таким образом, помимо монитора безопасности и брокера сообщений  получаем пять доверенных компонентов: Сentral, complex, internal navigation, crypto, HMI, sensors


В результате были сформулированы 6 наиболее вероятных сценариев нарушения ЦБ:

- Перезапись "чувствительных" данных при повторном заказе;

- Ввод паролей не в пункте назначения;

- Перебор паролей;

- Получение неверных координат;

- Скрытые поля и их использование для code injection;

- Взлом Communication как открытой точки доступа в сеть.

### Политики безопасности 


```python {lineNo:true}
ordering = False

def check_operation(id, details):
    global ordering
    authorized = False
    print(f"[info] checking policies for event {id},"\
          f" {details['source']}->{details['deliver_to']}: {details['operation']}")
    src = details['source']
    dst = details['deliver_to']
    operation = details['operation']
    if not ordering:
        if  src == 'communication' and dst == 'central' \
            and operation == 'ordering' and type(details['pincode']) == int \
                and type(details['x']) == int and type(details['y']) == int \
                and abs(details['x']) <= 200 and abs(details['y']) <= 200  and len(details) == 7 :
            authorized = True
            ordering = True
    if src == 'central' and dst == 'communication' \
        and operation == 'confirmation':
        authorized = True    
    if src == 'central' and dst == 'positioning' \
        and operation == 'count_direction':
        authorized = True    
    if src == 'positioning' and dst == 'central' \
        and operation == 'count_direction':
        authorized = True    
    if src == 'central' and dst == 'motion' \
        and operation == 'motion_start':
        authorized = True    
    if src == 'motion' and dst == 'positioning' \
        and operation == 'motion_start':
        authorized = True    
    if src == 'motion' and dst == 'positioning' \
        and operation == 'stop':
        authorized = True    
    if src == 'positioning' and dst == 'central' \
        and operation == 'stop':
        authorized = True
    if src == 'hmi' and dst == 'central' \
        and operation == 'pincoding':
        authorized = True    
    if src == 'central' and dst == 'sensors' \
        and operation == 'lock_opening':
        authorized = True
    if  src == 'sensors' and dst == 'central'\
        and operation == 'lock_closing':
        authorized = True
    if  src == 'central' and dst == 'communication'\
        and operation == 'ready':
        authorized = True
        ordering = False
    return authorized
```
